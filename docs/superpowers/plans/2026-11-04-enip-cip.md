# Phase 0 内核升级 + P2（EtherNet/IP + CIP）实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 P1 建好的协议无关内核补齐三处缺口（变体规划位置、codec 字段类型、变异层协议感知），还清两处 P1 欠账（串口服务端、CI），并交付 EtherNet/IP + CIP 协议族 —— 48 个操作类型、112 条覆盖条目。

| R12 | §6.2 说边界变体的 `instance_id` 上界是 0xFFFFFFFF | 上界取 **0xFFFF**（16 位实例段能容纳的最大值）。参数上界必须与承载它的字节宽度一致 —— 0xFFFFFFFF 会被静默截断成 0xFFFF，边界变体就会谎报自己的取值。`attribute_id` 0xFFFF、`class_id` 0xFF、`tag_count` 8 与规格一致。 |
| R13 | §5.2 的响应结构写「服务码 \| 保留 2 字节 \| 通用状态 \| 扩展状态大小」 | 响应格式是「`service \| 0x80`（1 字节）\| 保留（1 字节）\| 通用状态（1 字节）\| 扩展状态大小（1 字节，按字计）\| 扩展状态（size×2 字节）\| 数据」。**成功与失败的响应首字节都是 `service \| 0x80`**（`|0x80` 表示「这是响应」），错误由 `general_status` 承载；请求里没有任何保留字节。 |
| R14 | §5.5 只列出部分连接管理器操作，但 §6.1 要求 15 个 CM 操作全部可生成 | 15 个 CM 操作里只有 `forward_open`（ODVA 0x54）与 `unconnected_send`（ODVA 0x52）在 ODVA 里有对应服务，其余 13 个分配**合成码 0x60–0x6C**。`forward_close` 的 ODVA 码 0x4E 与标签服务的 `Read Modify Write Tag`（0x4E）撞车 —— 我们的目录要求服务码在三个族之间全局唯一，故它也用合成码。合成码 0x60–0x6C 与 ENIP 封装命令（0x0063–0x0066、0x006F）数值相近，但后者是 2 字节 `code_width`，两个数值空间由 `code_width` 区分。 |
| R15 | §8 白名单只描述「字段 → 锚点 + 偏移 + 宽度」，但 ENIP 封装层帧（ListIdentity 等）里根本没有 CIP 消息 | 白名单字段增加 **`guard`（守卫）** 概念：`guard: {offset: N, bytes: [...]}` 表示该字段只在「**从整帧起点**起第 N 字节等于给定字节序列」的帧里存在，否则该字段在此帧**不可变异**（`locate` 返回 `None`）。守卫的偏移相对整帧（字段自身的偏移才相对锚点）—— 守卫表达的是「这一帧长什么样」的整帧前提。ENIP 用 `guard: {offset: 0, bytes: [0x6F, 0x00]}` 把 `code`/`address` 限定在 SendRRData 帧。 |
| R16 | §6.1 把 48 个操作类型并列列出，没有说它们分属哪一层 | 目录里的操作分两类：**6 个封装层操作**（ENIP 帧 + 该命令自己的数据块）与 **42 个 CIP 应用层操作**（ENIP SendRRData 帧承载服务码 + 路径 + 数据）。两类靠 `code_width` 区分（封装层 2 字节、CIP 1 字节），避免两个数值空间撞车。所有 CIP 路径统一为 `20 <class8> 25 00 <instance16>`（尾部可追加属性段 `31 00 <attribute16>`）；标签服务把标签身份（tag_type + tag_id）放在**请求数据**里而不是路径里 —— 真实 Logix 用 ANSI 扩展符号段做路径，留到 P5 做真实采集时再对齐。 |
| R17 | §6.3 只说「元数据要给出操作类型信息」，没说应答怎么来 | ENIP 层的应答分三种来源：三个 `list_*` 操作用 `framing.LIST_REPLY_BUILDERS` 查表造应答数据块；`register_session` 的应答按布局造（协议版本 + 选项 + 会话句柄）；**封装层异常变体**是封装头里的非零状态码（`0x0001`），不是 CIP 错误响应 —— CIP 错误响应只属于 CIP 层的操作。 |

创建 `tests/test_protocol_variants.py`：

```python
"""协议无关的变体规划模块。

变体规划原本住在 Modbus 包里，但它不含任何 Modbus 知识。下沉之后
Modbus 包只做转发，行为逐字节不变。
"""

import ast
import inspect

from icsgen.protocols import variants as generic
from icsgen.protocols.modbus import variants as modbus


def _imported_modules(module) -> list[str]:
    """模块里 import 到的模块名。"""
    tree = ast.parse(inspect.getsource(module))
    names: list[str] = []
    for node in ast.walk(tree):
        if isinstance(node, ast.ImportFrom):
            names.append(node.module or "")
        elif isinstance(node, ast.Import):
            names.extend(alias.name for alias in node.names)
    return names


def test_modbus_module_forwards_to_generic_module():
    """Modbus 包里的变体模块只是转发 —— 同一个对象，不是两份实现。"""
    assert modbus.plan_variant is generic.plan_variant
    assert modbus.VariantPlan is generic.VariantPlan
    assert modbus.DEFAULT_EXCEPTION_CODE == generic.DEFAULT_EXCEPTION_CODE
    assert modbus.ILLEGAL_FUNCTION_EXCEPTION_CODE == generic.ILLEGAL_FUNCTION_EXCEPTION_CODE


def test_generic_module_does_not_import_modbus():
    """通用变体模块不许 import Modbus 包 —— 协议无关是硬约束。"""
    offenders = [name for name in _imported_modules(generic) if "modbus" in name]
    assert offenders == []


def test_generic_module_only_depends_on_the_kernel():
    """通用变体模块只依赖 codec 与 spec 两个内核模块。"""
    for name in _imported_modules(generic):
        assert name.startswith(("..codec", "..spec")), name


def test_generic_module_exposes_the_public_names():
    """公开名字齐全 —— 下游按名字导入，不靠 __getattr__ 兜底。"""
    for name in (
        "VariantPlan",
        "plan_variant",
        "DEFAULT_EXCEPTION_CODE",
        "ILLEGAL_FUNCTION_EXCEPTION_CODE",
    ):
        assert hasattr(generic, name), name
```

```python
def _pack_bitfield(f: Field, value: Any) -> bytes:
    """打包位域：成员从字节 0 的最高位开始依次向低位分配。

    位序与端序无关 —— endian 不影响成员的分配位置。
    """
    members = f.bit_fields or {}
    if not members:
        raise CodecError(f"字段 {f.name!r} 是位域但没有声明成员")
    if f.bit_width is None or f.bit_width % 8 != 0:
        raise CodecError(f"字段 {f.name!r} 的 bit_width 必须是 8 的倍数")
    total = sum(members.values())
    if total != f.bit_width:
        raise CodecError(
            f"字段 {f.name!r} 的成员位宽之和 {total} 与 bit_width {f.bit_width} 不一致"
        )
    if not isinstance(value, dict):
        raise CodecError(f"字段 {f.name!r} 是位域，值必须是字典")
    out = bytearray(f.bit_width // 8)
    bit_pos = 0
    for name, width in members.items():
        if name not in value:
            raise CodecError(f"字段 {f.name!r} 缺少成员 {name!r} 的值")
        member_value = int(value[name])
        if not 0 <= member_value < (1 << width):
            raise CodecError(
                f"字段 {f.name!r} 的成员 {name!r} 的值 {member_value} 超出 {width} 位"
            )
        for shift in range(width - 1, -1, -1):
            if (member_value >> shift) & 1:
                out[bit_pos // 8] |= 1 << (7 - bit_pos % 8)
            bit_pos += 1
    return bytes(out)
```

  - `MutationWhitelist.locate(concept: str, data: bytes) -> tuple[int, int, str] | None`
    —— **第二参数是整帧字节**（不再是帧长）。帧长由 `len(data)` 取得（`crc` 的负偏移需要它），守卫判定需要字节内容。

**白名单语义：**
- `fields` 的键固定四个概念：`length` / `code` / `address` / `crc`。协议没有某个概念就写 `null`。
- `offset` 为负表示**从帧尾往回数**（`-2` = 末两字节）；为正表示相对 `anchor` 起点。
- `anchor` 指相对哪一段定位，锚点偏移在协议的 `anchors` 映射里给出。默认锚点 `frame`（值为 0）。
- `width` 是字段字节数，`endian` 是 `big` / `little`。
- `min_value` 是「改成另一个值」时允许的取值下界（不含）。Modbus 的功能码下界是 1（0 不是有效功能码）。
- `guard`（可选）是**守卫**：形如 `{offset: N, bytes: [..]}`，表示「从整帧起点起第 N 字节开始的后缀必须逐字节等于给定字节」。守卫不成立时该字段在当前帧里**不存在**，规则返回 `None`（不适用）。
  —— 存在的理由：ENIP 的封装层帧（ListIdentity、RegisterSession 等）里根本没有 CIP 消息，`code`/`address` 只在 SendRRData 帧里才有意义。用守卫表达「这个概念只在某类帧里存在」，比让协议自己写分支更贴近声明式的做法。

**规则语义（改写后）：**
- `length_field_corrupt` / `address_corrupt`：读出白名单字段的整数值，从 `[min_value, 2^(8*width))` 里挑一个与当前值不同的写回。
- `func_code_corrupt`：同上，但**只改 1 字节**（写回时高位清零）—— 与现状一致：Modbus 的功能码是单字节。
   —— 实现口径：`func_code_corrupt` 取白名单 `code` 的**第一个字节**做「改成另一个值」。宽度大于 1 时只改首字节（低位在 ENIP/CIP 里才是有效位）。
- `crc_corrupt`：把白名单 `crc` 字段的**最后一个字节**取反（`^= 0xFF`）。且要求该字段前面至少还有 1 字节（校验字段得有被校验的本体）。
- 协议没有对应概念，或白名单为 `None` → 该规则不适用（返回 `None`）。

创建 `icsgen/codec/mutation.py`：

```python
"""变异字段白名单：协议把「哪个字节是哪个字段」声明成数据。

变异规则本身与协议无关 —— 翻转 bit、截断、篡改长度这些动作对任何协议
都一样。协议相关的是「长度字段在哪几个字节」。本模块把这件事从代码里
挪到 YAML 声明里：新增协议只要加一个 mutation.yaml，mutate/ 里的代码
一行都不用改。

白名单文件形如::

    protocol: modbus
    anchors:
      frame: 0
    fields:
      length: {offset: 4, width: 2, endian: big, min_value: 0}
      code:   {offset: 0, width: 1, endian: big, min_value: 1}
      crc:    null

offset 为负表示从帧尾往回数；anchor 指明相对哪一段定位，锚点偏移由
anchors 给出。fields 的值写 null 表示该协议没有这个概念。

字段还可以带 guard::

    code: {offset: 0, width: 1, endian: little, min_value: 1,
           guard: {offset: 0, bytes: [0x6F, 0x00]}}

guard 表示「从**整帧起点**起第 offset 字节开始的后缀必须逐字节等于 bytes」——
守卫不成立时该字段在当前帧里不存在，locate 返回 None。
守卫的偏移相对整帧（字段自身的偏移相对锚点）：守卫表达的是
「这一帧长什么样」的整帧前提，与字段落在哪个锚点无关。
"""

from __future__ import annotations

from dataclasses import dataclass
from pathlib import Path

import yaml
from pydantic import BaseModel, ConfigDict

#: 变异规则关心的字段概念，固定四个
CONCEPTS: tuple[str, ...] = ("length", "code", "address", "crc")


class GuardModel(BaseModel):
    """守卫：该字段只在满足条件的帧里存在。"""

    model_config = ConfigDict(extra="forbid")

    offset: int = 0
    bytes: list[int] = []


class FieldLocationModel(BaseModel):
    """白名单里一个字段概念的位置声明。"""

    model_config = ConfigDict(extra="forbid")

    offset: int
    width: int = 1
    endian: str = "big"
    anchor: str = "frame"
    min_value: int = 0
    guard: GuardModel | None = None


class WhitelistModel(BaseModel):
    """白名单文件的内容。"""

    model_config = ConfigDict(extra="forbid")

    protocol: str
    anchors: dict[str, int] = {}
    fields: dict[str, FieldLocationModel | None] = {}


@dataclass(frozen=True)
class Guard:
    """守卫：从整帧起点起第 offset 字节开始的后缀必须等于 data。"""

    offset: int
    data: bytes


@dataclass(frozen=True)
class FieldLocation:
    """字段概念在帧里的位置。"""

    offset: int
    width: int
    endian: str
    anchor: str
    min_value: int
    guard: Guard | None = None


@dataclass(frozen=True)
class MutationWhitelist:
    """一个协议的变异字段白名单。"""

    protocol: str
    anchors: dict[str, int]
    fields: dict[str, FieldLocation | None]

    def _anchor_base(self, anchor: str) -> int:
        base = self.anchors.get(anchor)
        if base is None:
            raise KeyError(
                f"白名单 {self.protocol!r} 引用了未声明的锚点 {anchor!r}"
            )
        return base

    def _guard_holds(self, location: FieldLocation, data: bytes) -> bool:
        """守卫是否成立。

        守卫的偏移相对**整帧起点**，与字段自身落在哪个锚点无关。
        """
        guard = location.guard
        if guard is None:
            return True
        start = guard.offset
        if start < 0:
            start += len(data)
        if start < 0 or start + len(guard.data) > len(data):
            return False
        return data[start : start + len(guard.data)] == guard.data

    def locate(self, concept: str, data: bytes) -> tuple[int, int, str] | None:
        """求某个概念的 (绝对偏移, 宽度, 端序)。

        协议没有这个概念、或该概念在本帧里不存在（守卫不成立）时返回 None
        —— 对应的变异规则不适用。
        """
        location = self.fields.get(concept)
        if location is None:
            return None
        if not self._guard_holds(location, data):
            return None
        if location.offset < 0:
            absolute = len(data) + location.offset
        else:
            absolute = self._anchor_base(location.anchor) + location.offset
        return absolute, location.width, location.endian

    def min_value(self, concept: str) -> int:
        """某个概念的取值下界（不含）。"""
        location = self.fields.get(concept)
        return location.min_value if location is not None else 0


def load_whitelist(path: Path) -> MutationWhitelist:
    """从 YAML 文件加载白名单。"""
    raw = yaml.safe_load(path.read_text(encoding="utf-8"))
    model = WhitelistModel.model_validate(raw)
    unknown = sorted(set(model.fields) - set(CONCEPTS))
    if unknown:
        raise ValueError(
            f"白名单 {path} 声明了未知的字段概念 {unknown}，可用概念：{list(CONCEPTS)}"
        )
    fields: dict[str, FieldLocation | None] = {}
    for name, location in model.fields.items():
        if location is None:
            fields[name] = None
            continue
        if location.endian not in ("big", "little"):
            raise ValueError(
                f"白名单 {path} 的字段 {name!r} 的端序非法：{location.endian!r}"
            )
        if location.width < 1:
            raise ValueError(
                f"白名单 {path} 的字段 {name!r} 的宽度必须至少为 1"
            )
        guard = None
        if location.guard is not None:
            guard = Guard(
                offset=location.guard.offset,
                data=bytes(location.guard.bytes),
            )
        fields[name] = FieldLocation(
            offset=location.offset,
            width=location.width,
            endian=location.endian,
            anchor=location.anchor,
            min_value=location.min_value,
            guard=guard,
        )
    return MutationWhitelist(
        protocol=model.protocol,
        anchors=dict(model.anchors),
        fields=fields,
    )
```

```python
def _set_field(
    data: bytes,
    rng: random.Random,
    whitelist: MutationWhitelist | None,
    concept: str,
    width: int | None = None,
) -> bytes | None:
    """把白名单里某个概念的字段改成另一个值。

    概念在当前协议上不存在、或字段在帧里放不下时返回 None（规则不适用）。
    width 只改字段的前若干字节 —— 功能码类字段只动低位那一个字节。
    """
    if whitelist is None:
        return None
    located = whitelist.locate(concept, data)
    if located is None:
        return None
    offset, field_width, endian = located
    target_width = field_width if width is None else min(width, field_width)
    if offset < 0 or offset + field_width > len(data):
        return None
    current = int.from_bytes(data[offset : offset + field_width], endian)
    limit = 1 << (8 * target_width)
    candidates = [
        value
        for value in range(whitelist.min_value(concept), limit)
        if value != current
    ]
    if not candidates:
        return None
    new_value = rng.choice(candidates)
    buf = bytearray(data)
    buf[offset : offset + target_width] = new_value.to_bytes(target_width, endian)
    return bytes(buf)

def _crc_corrupt(
    data: bytes, rng: random.Random, whitelist: MutationWhitelist | None

    """破坏帧尾校验字段的最后一个字节（位置由协议白名单声明）。"""
    if whitelist is None:
        return None
    located = whitelist.locate("crc", data)
    if located is None:
        return None
    offset, width, _endian = located
    if offset < 1 or offset + width > len(data):
        return None
    buf = bytearray(data)
    buf[offset + width - 1] ^= 0xFF
    return bytes(buf)
```

- Produces:
  - `icsgen.server.modbus_server.ModbusSerialServer`：`__init__(self, role="plc", unit_id=1, device: str | None = None)`、`start()`、`stop()`、`device_path` 属性、`address` 属性（`serial://<设备路径>`）
  - `icsgen.server.modbus_server.run_modbus_server(transport, host, port, role)` 在 `transport == "serial"` 时走串口服务端

**设计：**
- 用 `pty.openpty()` 造一对伪终端：master 端由服务端读写，slave 端的设备路径由 `os.ttyname(slave_fd)` 得到。外部程序可以打开这个路径当成真实串口用 —— 这正是「经 pty 伪终端注入真实串口帧」的落地方式。
- 服务端在 master 端累积字节，按功能码算出 RTU 请求帧的长度，切出完整帧后应答。
- 请求帧长度表：功能码 1/2/3/4/5/6/8/0x2B → 8 字节（地址 1 + 功能码 1 + 数据 4 + CRC 2）；15/16 → 读第 6 字节的字节计数，总长 = 9 + 字节计数；其余功能码按 8 字节处理。
- 伪终端要调成原始模式（`tty.setraw`）：默认行规程会回显（master 写出的内容又送回 master 的读队列）、按行缓冲、还把 `0x03` 当中断字符（应答里出现 `0x03` 时整个输入队列会被冲掉）。原始模式下伪终端才和真实串口一致。
- 读写循环用 `select` 带超时地轮询，这样 `stop()` 不用等读阻塞自然结束。
- 应答：读命令回「功能码 + 字节计数 + 数据」（数据按请求的 quantity 长度补零）；写命令回显请求；未知功能码回 Modbus 异常响应（功能码 | 0x80 + 0x01 非法功能码）。
- `role == "client"` 时反向：客户端在 master 端发起请求，从 slave 端读应答。

```python
#: RTU 请求帧的固定长度：地址 1 + 功能码 1 + 数据 4 + CRC 2
_FIXED_REQUEST_LENGTH = 8

#: 需要读字节计数才能定长的功能码
_VARIABLE_REQUEST_FUNCTIONS = (15, 16)

#: 读写循环的轮询间隔（秒）—— 停止信号最多延迟这么久
_POLL_INTERVAL = 0.2


def _request_length(buffer: bytes) -> int | None:
    """从累积的字节里判断当前 RTU 请求帧的长度。

    还不够判断时返回 None。带字节计数的功能码要读到第 6 个字节才知道
    总长。长度含帧尾的 2 字节 CRC —— `parse_rtu` 要校验它。
    """
    if len(buffer) < 2:
        return None
    function = buffer[1]
    if function in _VARIABLE_REQUEST_FUNCTIONS:
        if len(buffer) < 7:
            return None
        return 9 + buffer[6]
    return _FIXED_REQUEST_LENGTH


def _response_pdu(function: int, request_pdu: bytes) -> bytes:
    """按功能码构造应答 PDU。"""
    if function in (1, 2, 3, 4):
        # 读命令：字节计数 + 数据。请求里的数量决定数据长度。
        # PDU 是「功能码 + 数据」，数量在 PDU 的第 3-4 字节。
        quantity = int.from_bytes(request_pdu[3:5], "big") if len(request_pdu) >= 5 else 1
        if function in (1, 2):
            byte_count = (quantity + 7) // 8
        else:
            byte_count = quantity * 2
        return bytes([function, byte_count]) + bytes(byte_count)
    if function in (5, 6, 8, 0x2B):
        # 写命令与诊断：原样回显
        return bytes([function]) + request_pdu[2:]
    if function in (15, 16):
        return bytes([function]) + request_pdu[2:6]
    # 未知功能码：非法功能码异常
    return bytes([function | 0x80, 0x01])


class ModbusSerialServer:
    """经伪终端（pty）承载 RTU 帧的 Modbus 服务端。

    pty 造出一对伪终端：服务端读写 master 端，外部程序打开 slave 端的
    设备路径就能像用真实串口一样收发 RTU 帧 —— 这让「真实串口时序」
    这类要求有地方落脚。
    """

    def __init__(self, role: str = "plc", unit_id: int = 1, device: str | None = None) -> None:
        if role not in {"plc", "client"}:
            raise ValueError(f"不支持的角色 {role!r}，可选 plc / client")
        self.role = role
        self.unit_id = unit_id
        self._device = device
        self._master_fd: int | None = None
        self._slave_fd: int | None = None
        self._thread: threading.Thread | None = None
        self._stop_event = threading.Event()

    @property
    def device_path(self) -> str:
        """设备路径。指定了外部设备就用它，否则用 pty 的 slave 端。"""
        if self._device is not None:
            return self._device
        if self._slave_fd is None:
            raise RuntimeError("串口服务端尚未启动")
        return os.ttyname(self._slave_fd)

    @property
    def address(self) -> str:
        """服务地址。"""
        return f"serial://{self.device_path}"

    def start(self) -> None:
        """启动服务。"""
        if self._device is None:
            self._master_fd, self._slave_fd = pty.openpty()
            self._make_raw()
        else:
            self._master_fd = os.open(self._device, os.O_RDWR | os.O_NOCTTY)
        self._thread = threading.Thread(target=self._serve, daemon=True)
        self._thread.start()

    def _make_raw(self) -> None:
        """把伪终端调成原始模式。

        默认的行规程会做三件不该做的事：回显（master 写出去的内容又送回
        master 的读队列，服务端会把自己刚写的应答当成请求）、规范模式
        （按行缓冲）、以及把 0x03 当成中断字符（应答里出现 0x03 时，
        整个输入队列会被冲掉）。原始模式下伪终端才和真实串口一致。
        """
        assert self._slave_fd is not None
        tty.setraw(self._slave_fd)

    def stop(self) -> None:
        """停止服务。"""
        self._stop_event.set()
        if self._thread is not None:
            self._thread.join(timeout=STARTUP_TIMEOUT)
            self._thread = None
        for fd in (self._master_fd, self._slave_fd):
            if fd is not None:
                try:
                    os.close(fd)
                except OSError:
                    pass
        self._master_fd = None
        self._slave_fd = None

    def _serve(self) -> None:
        """读写循环：累积字节、切出完整帧、应答。"""
        assert self._master_fd is not None
        buffer = bytearray()
        while not self._stop_event.is_set():
            try:
                ready, _, _ = select.select([self._master_fd], [], [], _POLL_INTERVAL)
            except (OSError, ValueError):
                return
            if not ready:
                continue
            try:
                chunk = os.read(self._master_fd, 512)
            except OSError:
                return
            if not chunk:
                return
            buffer.extend(chunk)
            while True:
                length = _request_length(buffer)
                if length is None or len(buffer) < length:
                    break
                frame = bytes(buffer[:length])
                del buffer[:length]
                self._handle(frame)

    def _handle(self, frame: bytes) -> None:
        """处理一帧 RTU 请求并写回应答。"""
        try:
            parsed = parse_rtu(frame)
        except ValueError:
            return
        if parsed["unit_id"] != self.unit_id:
            return
        pdu = parsed["pdu"]
        if not pdu:
            return
        response_pdu = _response_pdu(pdu[0], pdu)
        os.write(self._master_fd, build_rtu(self.unit_id, response_pdu))
```

  - `build_send_data(command, cp, session=0, context=b"\x00" * 8, interface=0,
    timeout=0xFFFF, type_id=ITEM_UNCONNECTED_DATA, status=0) -> bytes`

  - `build_list_identity_reply(...) -> bytes`、`build_list_interfaces_reply(...) -> bytes`
  - `framing.LIST_REPLY_BUILDERS: dict[int, Callable[[], bytes]]` —— 命令码 → 应答数据块
    的构造器（ListServices / ListIdentity / ListInterfaces 三个）
  - `parse_frame(data: bytes) -> dict` —— 键：`command` / `length` / `session` / `status` /
    `context` / `options` / `payload`
  - `parse_send_data(payload: bytes) -> dict` —— 键：`interface` / `timeout` /
    `items`（每项 `type_id` / `length` / `data`）

**为什么要两个「只有数据块」的构造器：** 适配器在编解码时要分别处理
「请求帧」与「应答数据块」—— 应答的 CIP 载荷不含 24 字节封装头。
如果只有 `build_send_data`（整帧），适配器就得先造一整帧再切掉 24 字节头，
那是在用封装层的结构去切应用层的数据，很脆。`build_send_data_payload` /
`build_register_session_payload` 直接给出数据块，`build_send_data` /
`build_register_session` 在其之上拼封装头 —— 整帧的黄金字节因此不变。

```python
"""ENIP 封装层：24 字节头 + 命令数据块。

字段结构对照 ODVA CIP Vol 2 与 Scapy 的 `scapy.contrib.enipTCP`。
**全程小端** —— 这与 Modbus 相反，是最容易写错的地方。

头（24 字节）：

===== ======== ==================================
偏移  长度  字段
===== ======== ==================================
0     2      command（uint16 LE）
2     2      length（uint16 LE，后续数据字节数）
4     4      session（uint32 LE，会话句柄）
8     4      status（uint32 LE，0 表示成功）
12    8      sender_context（原样回送）
20    4      options（uint32 LE，0）
===== ======== ==================================
"""

from __future__ import annotations

import struct
from typing import Callable

#: 封装头长度（字节）
HEADER_LEN = 24

#: ENIP 的默认端口
DEFAULT_PORT = 44818

#: 生成器使用的会话句柄：一个连接内的所有帧共用同一个句柄
SESSION_HANDLE = 0x00000001

#: 命令码（ODVA CIP Vol 2）
COMMAND_LIST_SERVICES = 0x0004
COMMAND_LIST_IDENTITY = 0x0063
COMMAND_LIST_INTERFACES = 0x0064
COMMAND_REGISTER_SESSION = 0x0065
COMMAND_UNREGISTER_SESSION = 0x0066
COMMAND_SEND_RR_DATA = 0x006F
COMMAND_SEND_UNIT_DATA = 0x0070

COMMAND_NAMES: dict[int, str] = {
    COMMAND_LIST_SERVICES: "ListServices",
    COMMAND_LIST_IDENTITY: "ListIdentity",
    COMMAND_LIST_INTERFACES: "ListInterfaces",
    COMMAND_REGISTER_SESSION: "RegisterSession",
    COMMAND_UNREGISTER_SESSION: "UnregisterSession",
    COMMAND_SEND_RR_DATA: "SendRRData",
    COMMAND_SEND_UNIT_DATA: "SendUnitData",
}

#: ItemData 的类型码
ITEM_UNCONNECTED_DATA = 0x00B2
ITEM_CONNECTED_DATA = 0x00B1

#: 身份项的类型码与接口项的类型码
ITEM_IDENTITY = 0x000C
ITEM_INTERFACE = 0x0100


def build_context(transaction_id: int) -> bytes:
    """8 字节发送上下文：事务 id（小端）占低 4 字节，高 4 字节为 0。

    请求与响应回送同一段上下文，两者因此可配对。
    """
    return struct.pack("<I", transaction_id & 0xFFFFFFFF) + b"\x00" * 4


def build_header(
    command: int,
    length: int,
    session: int = 0,
    status: int = 0,
    context: bytes = b"\x00" * 8,
    options: int = 0,
) -> bytes:
    """24 字节封装头。"""
    if len(context) != 8:
        raise ValueError("发送上下文必须是 8 字节")
    return (
        struct.pack("<H", command & 0xFFFF)
        + struct.pack("<H", length & 0xFFFF)
        + struct.pack("<I", session & 0xFFFFFFFF)
        + struct.pack("<I", status & 0xFFFFFFFF)
        + context
        + struct.pack("<I", options & 0xFFFFFFFF)
    )


def build_frame(
    command: int,
    payload: bytes = b"",
    session: int = 0,
    context: bytes = b"\x00" * 8,
    status: int = 0,
) -> bytes:
    """封装头 + 数据块。length 字段由数据块长度推出。"""
    return build_header(
        command, len(payload), session=session, status=status, context=context
    ) + payload


def build_register_session_payload() -> bytes:
    """RegisterSession 的数据块：协议版本 2 + 选项标志 2（各 2 字节小端）。

    裁定 R3：规格 §4.3 写的 6 字节不存在 —— ODVA CIP Vol 2 与 Scapy 的
    `ENIPRegisterSession` 都是 4 字节。
    """
    return struct.pack("<HH", 1, 0)


def build_register_session(
    context: bytes = b"\x00" * 8, session: int = 0, status: int = 0
) -> bytes:
    """RegisterSession 帧：命令 0x0065 + 4 字节数据块（协议版本 + 选项标志）。"""
    return build_frame(
        COMMAND_REGISTER_SESSION,
        build_register_session_payload(),
        session=session,
        context=context,
        status=status,
    )


def build_send_data_payload(
    cp: bytes,
    interface: int = 0,
    timeout: int = 0xFFFF,
    type_id: int = ITEM_UNCONNECTED_DATA,
) -> bytes:
    """SendRRData / SendUnitData 的数据块：接口句柄 + 超时 + 一个 ItemData。

    ItemData 的长度字段由 CIP 消息长度推出。
    """
    return (
        struct.pack("<I", interface & 0xFFFFFFFF)
        + struct.pack("<H", timeout & 0xFFFF)
        + struct.pack("<H", 1)
        + struct.pack("<HH", type_id & 0xFFFF, len(cp))
        + cp
    )


def build_send_data(
    command: int,
    cp: bytes,
    session: int = 0,
    context: bytes = b"\x00" * 8,
    interface: int = 0,
    timeout: int = 0xFFFF,
    type_id: int = ITEM_UNCONNECTED_DATA,
    status: int = 0,
) -> bytes:
    """SendRRData / SendUnitData 帧：命令 + 数据块。"""
    payload = build_send_data_payload(
        cp, interface=interface, timeout=timeout, type_id=type_id
    )
    return build_frame(command, payload, session=session, context=context, status=status)


def build_list_services_reply(name: bytes = b"Communications") -> bytes:
    """ListServices 的应答数据块：版本 + 能力标志 + 16 字节服务名。"""
    return struct.pack("<HH", 1, 0) + name.ljust(16, b"\x00")[:16]


def build_list_identity_reply(
    vendor_id: int = 1,
    device_type: int = 0x000C,
    product_code: int = 1,
    revision: int = 1,
    status: int = 0x0030,
    serial_number: int = 1,
    product_name: bytes = b"icsgen",
) -> bytes:
    """ListIdentity 的应答数据块：项数 + 一个身份项（类型 0x000C）。"""
    body = (
        struct.pack("<HHHHH", vendor_id, device_type, product_code, revision, status)
        + struct.pack("<I", serial_number)
        + bytes([len(product_name)])
        + product_name
    )
    item = struct.pack("<HH", ITEM_IDENTITY, len(body)) + body
    return struct.pack("<H", 1) + item


def build_list_interfaces_reply(
    interface_handle: int = 0,
    interface_type: int = 0x0000,
    state: int = 0x0000,
) -> bytes:
    """ListInterfaces 的应答数据块：项数 + 一个接口项（类型 0x0100）。"""
    body = struct.pack("<IHH", interface_handle, interface_type, state)
    item = struct.pack("<HH", ITEM_INTERFACE, len(body)) + body
    return struct.pack("<H", 1) + item


def parse_frame(data: bytes) -> dict:
    """解析一个封装帧，返回头字段与数据块。"""
    if len(data) < HEADER_LEN:
        raise ValueError(f"ENIP 帧不足 {HEADER_LEN} 字节：{len(data)}")
    command, length = struct.unpack("<HH", data[0:4])
    session, status = struct.unpack("<II", data[4:12])
    context = data[12:20]
    options = struct.unpack("<I", data[20:24])[0]
    return {
        "command": command,
        "length": length,
        "session": session,
        "status": status,
        "context": context,
        "options": options,
        "payload": data[HEADER_LEN:],
    }


def parse_send_data(payload: bytes) -> dict:
    """解析 SendRRData / SendUnitData 的数据块。

    返回 `interface` / `timeout` / `items`；每个 ItemData 项含
    `type_id` / `length` / `data`。
    """
    if len(payload) < 8:
        raise ValueError(f"SendData 数据块不足 8 字节：{len(payload)}")
    interface = struct.unpack("<I", payload[0:4])[0]
    timeout = struct.unpack("<H", payload[4:6])[0]
    count = struct.unpack("<H", payload[6:8])[0]
    offset = 8
    items = []
    for _ in range(count):
        if offset + 4 > len(payload):
            raise ValueError("ItemData 头被截断")
        type_id, length = struct.unpack("<HH", payload[offset:offset + 4])
        offset += 4
        items.append({
            "type_id": type_id,
            "length": length,
            "data": payload[offset:offset + length],
        })
        offset += length
    return {"interface": interface, "timeout": timeout, "items": items}


#: 查询类命令 → 应答数据块构造器。适配器按命令码查表即可。
LIST_REPLY_BUILDERS: dict[int, Callable[[], bytes]] = {
    COMMAND_LIST_SERVICES: build_list_services_reply,
    COMMAND_LIST_IDENTITY: build_list_identity_reply,
    COMMAND_LIST_INTERFACES: build_list_interfaces_reply,
}
```

**消息结构（实现必须照此，与规格 §5.1/§5.2 的旧写法冲突时以本表为准 —— 裁定 R7/R13）：**

```
请求：服务码(1) | 路径长度(1，按字计) | 路径(路径长度×2 字节) | 请求数据
响应：服务码|0x80(1) | 保留(1) | 通用状态(1) | 扩展状态大小(1，按字计) | 扩展状态(大小×2 字节) | 响应数据
```

- 请求里**没有**保留字节，**没有** service_data 字段。
- 响应首字节是 `服务码 | 0x80`，成功与失败都一样；失败由通用状态承载。
- 所有 CIP 服务码都是 **1 字节**（掩码 `0x7F`，最高位是响应标志）。

**EPATH 段编码（裁定 R9/R11）：**

| 段 | 类型字节 | 取值 | 段长 |
|---|---|---|---|
| 类（8 位） | `0x20` | `20 <class8>` | 2 |
| 实例（16 位） | `0x25` | `25 00 <instance16 小端>` | 4 |
| 属性（16 位） | `0x31` | `31 00 <attribute16 小端>` | 4 |
| 成员（16 位） | `0x29` | `29 00 <member16 小端>` | 4 |
| 连接点（16 位） | `0x2D` | `2D 00 <point16 小端>` | 4 |
| 服务 id（8 位） | `0x38` | `38 <service8>` | 2 |
| 端口 | `0x00 \| port` | `00 <link>` | 2 |
| 简单符号 | `0x60 \| len` | `60\|len <名字>` | 1+len |
| ANSI 扩展符号 | `0x91` | `91 <len> <名字> [补齐]` | 2+len(+1) |
| 简单数据 | `0x80` | `80 <字数> <数据>` | 2+字数×2 |

- 段族由类型字节的高 3 位给出：端口 `0x00`、逻辑 `0x20`、网络 `0x40`、符号 `0x60`、数据 `0x80`。
- 逻辑段的类型字节里，位 3-2 是种类（类 `0x00` / 实例 `0x04` / 成员 `0x08` / 连接点 `0x0C` / 属性 `0x10` / 特殊 `0x14` / 服务 id `0x18`），位 1-0 是宽度（8 位 `0x00` / 16 位 `0x01` / 32 位 `0x02`）。
- 逻辑段采用 ODVA 的**非紧凑形式**（取值从字边界开始，16 位段是「类型字节 | 补齐字节 | 取值」）。这与 Wireshark `packet-cip.c` 的 `dissect_cia`（`packed=false` 分支）逐字节一致。
- 简单数据段的长度按**字**计；ANSI 扩展符号段的长度按**字节**计，奇数长度补一个补齐字节。

**服务码分配（裁定 R8/R14）：** 42 个 1 字节服务码在三个族之间**全局唯一**。

| 族 | 码 | 服务 |
|---|---|---|
| 通用 | 0x01 / 0x02 | Get_Attributes_All / Set_Attributes_All |
| 通用 | 0x05–0x09 | Reset / Start / Stop / Create / Delete |
| 通用 | 0x0A / 0x0D | Multiple_Service_Request / Apply_Attributes |
| 通用 | 0x0E / 0x10 | Get_Attribute_Single / Set_Attribute_Single |
| 通用 | 0x20–0x2B | 12 个合成码（见实现） |
| 标签 | 0x4C–0x4F | Read_Tag / Write_Tag / Read_Modify_Write_Tag / Read_Modify_Write_Tag_Fragmented |
| 连接管理器 | 0x52 / 0x54 | Unconnected_Send / Forward_Open |
| 连接管理器 | 0x60–0x6C | 13 个合成码（见实现） |

> `Forward_Close` 的 ODVA 号 0x4E 与标签服务 `Read_Modify_Write_Tag` 撞车，故用合成码 0x60。

创建 `icsgen/protocols/enip/epath.py`：

```python
"""CIP 的 EPATH：路径段的构造与解析。

段族由类型字节的高 3 位给出：端口 ``0x00``、逻辑 ``0x20``、网络 ``0x40``、
符号 ``0x60``、数据 ``0x80``。逻辑段的类型字节里，位 3-2 是段的种类（类 /
实例 / 成员 / 连接点 / 属性 / 特殊 / 服务 id），位 1-0 是取值的宽度
（8 位 / 16 位 / 32 位）。

逻辑段采用 ODVA 的**非紧凑形式**：每个段的取值从字边界开始 —— 8 位段是
「类型字节 | 取值」，16 位段是「类型字节 | 补齐字节 | 取值」，32 位段是
「类型字节 | 补齐字节 | 取值」。这与 Wireshark ``packet-cip.c`` 的
``dissect_cia``（``packed=false`` 分支）逐字节一致，也让实例号稳定落在
CIP 体内的偏移 6（``INSTANCE_OFFSET``）。
"""

from __future__ import annotations

from typing import Iterable

#: 段族（类型字节的高 3 位）
FAMILY_PORT = 0x00
FAMILY_LOGICAL = 0x20
FAMILY_NETWORK = 0x40
FAMILY_SYMBOLIC = 0x60
FAMILY_DATA = 0x80

#: 逻辑段的种类（类型字节的位 3-2）
KIND_CLASS = 0x00
KIND_INSTANCE = 0x04
KIND_MEMBER = 0x08
KIND_CONNECTION_POINT = 0x0C
KIND_ATTRIBUTE = 0x10
KIND_SPECIAL = 0x14
KIND_SERVICE_ID = 0x18

#: 逻辑段的取值宽度（类型字节的位 1-0）
FORMAT_8 = 0x00
FORMAT_16 = 0x01
FORMAT_32 = 0x02

#: 数据段的子类型（类型字节的低 5 位）
DATA_SEG_SIMPLE = 0x00
DATA_SEG_SYMBOL = 0x11

#: 种类 → 名字
KIND_NAMES: dict[int, str] = {
    KIND_CLASS: "class",
    KIND_INSTANCE: "instance",
    KIND_MEMBER: "member",
    KIND_CONNECTION_POINT: "connection_point",
    KIND_ATTRIBUTE: "attribute",
    KIND_SPECIAL: "special",
    KIND_SERVICE_ID: "service_id",
}

#: 实例号在 CIP 请求体内的偏移（非紧凑形式下路径以「类段 | 实例段」开头）
INSTANCE_OFFSET = 6


def _logical(kind: int, value: int, width: int) -> bytes:
    """构造一个逻辑段（非紧凑形式）。"""
    if width == 8:
        return bytes([FAMILY_LOGICAL | kind | FORMAT_8, value & 0xFF])
    if width == 16:
        head = bytes([FAMILY_LOGICAL | kind | FORMAT_16, 0x00])
        return head + (value & 0xFFFF).to_bytes(2, "little")
    if width == 32:
        head = bytes([FAMILY_LOGICAL | kind | FORMAT_32, 0x00])
        return head + (value & 0xFFFFFFFF).to_bytes(4, "little")
    raise ValueError(f"逻辑段的宽度只能是 8 / 16 / 32，实际 {width}")


def build_class(class_id: int) -> bytes:
    """类段（8 位）。"""
    return _logical(KIND_CLASS, class_id, 8)


def build_instance(instance_id: int) -> bytes:
    """实例段（16 位）。"""
    return _logical(KIND_INSTANCE, instance_id, 16)


def build_attribute(attribute_id: int) -> bytes:
    """属性段（16 位）。"""
    return _logical(KIND_ATTRIBUTE, attribute_id, 16)


def build_member(member_id: int) -> bytes:
    """成员段（16 位）。"""
    return _logical(KIND_MEMBER, member_id, 16)


def build_connection_point(point_id: int) -> bytes:
    """连接点段（16 位）。"""
    return _logical(KIND_CONNECTION_POINT, point_id, 16)


def build_service_id(service_id: int) -> bytes:
    """服务 id 段（只有 8 位形式）。"""
    return bytes([FAMILY_LOGICAL | KIND_SERVICE_ID, service_id & 0xFF])


def build_port(port: int) -> bytes:
    """端口段：类型字节低 4 位是端口号，后跟 1 个链路地址字节。"""
    return bytes([FAMILY_PORT | (port & 0x0F), 0x00])


def build_data(value: bytes) -> bytes:
    """简单数据段：长度按字计。"""
    if len(value) % 2 != 0:
        raise ValueError(f"简单数据段的数据必须是偶数字节，实际 {len(value)}")
    return bytes([FAMILY_DATA, len(value) // 2]) + value


def build_symbol(name: bytes) -> bytes:
    """简单符号段：类型字节低 5 位是名字长度（1..31）。"""
    if not 1 <= len(name) <= 31:
        raise ValueError(f"简单符号段的名字长度必须在 1..31 之间，实际 {len(name)}")
    return bytes([FAMILY_SYMBOLIC | len(name)]) + name


def build_extended_symbol(name: bytes) -> bytes:
    """ANSI 扩展符号段：类型字节 | 长度字节 | 名字 | 补齐字节。"""
    out = bytes([FAMILY_DATA | DATA_SEG_SYMBOL, len(name)]) + name
    if len(name) % 2:
        out += b"\x00"
    return out


def build_path(segments: Iterable[bytes]) -> bytes:
    """把若干段拼成一条路径。"""
    return b"".join(segments)


def _parse_logical(data: bytes, offset: int) -> tuple[dict, int]:
    """解析一个逻辑段，返回（段描述，消耗的字节数）。"""
    type_byte = data[offset]
    kind = type_byte & 0x1C
    fmt = type_byte & 0x03
    if kind == KIND_SERVICE_ID:
        return (
            {"family": "logical", "kind": "service_id", "width": 8, "value": data[offset + 1]},
            2,
        )
    if fmt == FORMAT_8:
        return (
            {"family": "logical", "kind": KIND_NAMES[kind], "width": 8, "value": data[offset + 1]},
            2,
        )
    if fmt == FORMAT_16:
        value = int.from_bytes(data[offset + 2 : offset + 4], "little")
        return ({"family": "logical", "kind": KIND_NAMES[kind], "width": 16, "value": value}, 4)
    if fmt == FORMAT_32:
        value = int.from_bytes(data[offset + 2 : offset + 6], "little")
        return ({"family": "logical", "kind": KIND_NAMES[kind], "width": 32, "value": value}, 6)
    raise ValueError(f"未知的逻辑段格式位 {fmt:#04x}")


def parse_path(data: bytes) -> list[dict]:
    """把一条路径拆成若干段描述。"""
    segments: list[dict] = []
    offset = 0
    while offset < len(data):
        type_byte = data[offset]
        family = type_byte & 0xE0
        if family == FAMILY_LOGICAL:
            segment, size = _parse_logical(data, offset)
            segments.append(segment)
            offset += size
        elif family == FAMILY_PORT:
            segments.append({"family": "port", "port": type_byte & 0x0F})
            offset += 2
        elif family == FAMILY_DATA:
            sub = type_byte & 0x1F
            size = data[offset + 1]
            if sub == DATA_SEG_SIMPLE:
                payload = data[offset + 2 : offset + 2 + size * 2]
                segments.append(
                    {"family": "data", "kind": "simple", "length": size * 2, "value": payload}
                )
                offset += 2 + size * 2
            elif sub == DATA_SEG_SYMBOL:
                payload = data[offset + 2 : offset + 2 + size]
                segments.append(
                    {
                        "family": "data",
                        "kind": "extended_symbol",
                        "length": size,
                        "value": payload,
                    }
                )
                offset += 2 + size + (size % 2)
            else:
                raise ValueError(f"未知的数据段子类型 {sub:#04x}")
        elif family == FAMILY_SYMBOLIC:
            size = type_byte & 0x1F
            segments.append(
                {"family": "symbolic", "kind": "symbol", "length": size, "value": data[offset + 1 : offset + 1 + size]}
            )
            offset += 1 + size
        elif family == FAMILY_NETWORK:
            raise ValueError("网络段尚未实现 —— 本期的路径只用逻辑段、符号段与数据段")
        else:
            raise ValueError(f"未知的路径段族 {family:#04x}")
    return segments
```

```python
    return GENERAL_STATUS.get(code, f"Status_0x{code:02X}")


def build_request(service: int, path: bytes, data: bytes = b"") -> bytes:
    """构造 CIP 请求：服务码 | 路径长度（字）| 路径 | 请求数据。"""
    if len(path) % 2 != 0:
        raise ValueError(f"CIP 请求的路径必须是偶数字节，实际 {len(path)}")
    return bytes([service & CIP_SC_MASK, len(path) // 2]) + path + data


def parse_request(data: bytes) -> dict:
    """解析 CIP 请求。"""
    if len(data) < 2:
        raise ValueError("CIP 请求至少要有服务码与路径长度两个字节")
    service = data[0] & CIP_SC_MASK
    path_size = data[1]
    path = data[2 : 2 + path_size * 2]
    if len(path) != path_size * 2:
        raise ValueError(
            f"CIP 请求声明的路径是 {path_size} 字（{path_size * 2} 字节），实际只有 {len(path)} 字节"
        )
    return {
        "service": service,
        "path_size": path_size,
        "path": path,
        "data": data[2 + path_size * 2 :],
    }


def build_reply(
    service: int,
    general_status: int = 0,
    additional_status: bytes = b"",
    data: bytes = b"",
) -> bytes:
    """构造 CIP 响应：服务码|0x80 | 保留 | 通用状态 | 扩展状态大小（字）| 扩展状态 | 数据。"""
    if len(additional_status) % 2 != 0:
        raise ValueError(f"CIP 响应的扩展状态必须是偶数字节，实际 {len(additional_status)}")
    head = bytes(
        [
            (service & CIP_SC_MASK) | CIP_SC_RESPONSE_MASK,
            0x00,
            general_status & 0xFF,
            len(additional_status) // 2,
        ]
    )
    return head + additional_status + data


def parse_reply(data: bytes) -> dict:
    """解析 CIP 响应。"""
    if len(data) < 4:
        raise ValueError("CIP 响应至少要有四个字节的头")
    service = data[0] & CIP_SC_MASK
    general_status = data[2]
    size = data[3]
    additional = data[4 : 4 + size * 2]
    if len(additional) != size * 2:
        raise ValueError(
            f"CIP 响应声明的扩展状态是 {size} 字（{size * 2} 字节），实际只有 {len(additional)} 字节"
        )
    return {
        "service": service,
        "general_status": general_status,
        "additional_status": additional,
        "data": data[4 + size * 2 :],
    }


def build_error_reply(service: int, general_status: int, additional_status: bytes = b"") -> bytes:
    """构造一个失败响应（通用状态非 0）。"""
    return build_reply(service, general_status=general_status, additional_status=additional_status)
```

**目录的两种操作（裁定 R16/R17）：**

| 类别 | 数量 | 帧的形态 |
|---|---|---|
| 封装层操作 | 6 | ENIP 封装头 + 该命令自己的数据块（`send_rr_data` 例外：它带一段 CIP 消息） |
| CIP 应用层操作 | 42 | ENIP 封装头 + SendRRData 数据块 + CIP 消息（服务码 + 路径 + 数据） |

- 封装层操作的 `func_code` 是 ENIP 命令（2 字节），故 `code_width: 2`；CIP 操作的 `func_code` 是 CIP 服务码（1 字节），故 `code_width: 1`。
- 两个数值空间由 `code_width` 区分：连接管理器的合成码 `0x63`（1 字节）与 ENIP 命令 `0x0063`（2 字节）数值相近但不是同一个空间。
- **路径形态统一**：所有 CIP 服务的路径都是 `20 <class8> 25 00 <instance16>`，尾部可追加属性段 `31 00 <attribute16>`。路径参数不是布局字段（它们不进 codec 的字段序列），由适配器按 catalog 的参数拼装（Task 10）。
- 标签服务同样走 class+instance 路径，标签身份放在**请求数据**里（tag_type + tag_id）。真实 Logix 用 ANSI 扩展符号段做路径，P5 做真实采集时再对齐。

**覆盖条目数（裁定 R2）：** 16 个带参数的操作类型 3 变体（normal/boundary/exception）+ 32 个无参数的操作类型 2 变体（normal/exception）= 16×3 + 32×2 = **112** ≥ 110。

```python
"""ENIP / CIP 帧的协议级解析：把裸帧拆成封装头、数据块与 CIP 消息。

预览页要展示「命令 / 会话句柄 / CIP 服务码 / 路径 / 通用状态」，
这些是协议知识，留在协议层而不是 Web 层。
"""

from __future__ import annotations

from typing import Any

from ..base import BuildContext, FrameField, FrameView
from . import cip, epath, framing
from .layouts import EnipLayout


def _format(value: Any) -> str:
    """把解码出的取值格式化成显示用的一行。"""
    if isinstance(value, (bytes, bytearray)):
        return bytes(value).hex(" ")
    if isinstance(value, list):
        return ", ".join(_format(item) for item in value)
    return str(value)


def _format_path(segments: list[dict]) -> str:
    """路径段 → 一行可读文本。"""
    parts: list[str] = []
    for segment in segments:
        if segment["family"] == "logical":
            parts.append(f"{segment['kind']}={segment['value']}")
        elif segment["family"] == "data":
            parts.append(f"{segment['kind']}[{segment['length']}]")
        elif segment["family"] == "symbolic":
            parts.append(f"symbol[{segment['length']}]")
        else:
            parts.append(f"port={segment['port']}")
    return " / ".join(parts)


def _cip_fields(
    direction: str, cip_data: bytes
) -> tuple[list[FrameField], str, bool, int | None]:
    """解析 CIP 消息，返回（字段，摘要片段，是否异常，异常码）。"""
    if direction == "request":
        parsed = cip.parse_request(cip_data)
        fields = [
            FrameField(
                "CIP 服务码",
                f"0x{parsed['service']:02X} {cip.service_name(parsed['service'])}",
            ),
            FrameField("路径", _format_path(epath.parse_path(parsed["path"]))),
        ]
        if parsed["data"]:
            fields.append(FrameField("请求数据", _format(parsed["data"])))
        return fields, cip.service_name(parsed["service"]), False, None

    parsed = cip.parse_reply(cip_data)
    fields = [
        FrameField(
            "CIP 服务码",
            f"0x{parsed['service']:02X} {cip.service_name(parsed['service'])}",
        ),
        FrameField(
            "通用状态",
            f"0x{parsed['general_status']:02X} "
            f"{cip.general_status_name(parsed['general_status'])}",
        ),
    ]
    if parsed["additional_status"]:
        fields.append(FrameField("扩展状态", _format(parsed["additional_status"])))
    if parsed["data"]:
        fields.append(FrameField("响应数据", _format(parsed["data"])))
    status = parsed["general_status"]
    return fields, cip.general_status_name(status), status != 0, status


def inspect_frame(
    layout: EnipLayout, payload: bytes, ctx: BuildContext, direction: str
) -> FrameView:
    """解析一帧 ENIP 请求或响应。

    解析失败（帧过短、结构不符）不抛错，返回只含失败原因的 FrameView ——
    畸形帧本就是数据集的一部分，预览不该因此失败。
    """
    try:
        header = framing.parse_frame(payload)
    except ValueError as exc:
        return FrameView(summary=f"解析失败：{exc}")

    command = header["command"]
    fields = [
        FrameField("命令", f"0x{command:04X}"),
        FrameField("会话句柄", f"0x{header['session']:08X}"),
        FrameField("封装状态", f"0x{header['status']:08X}"),
        FrameField("长度", str(header["length"])),
    ]
    data = header["payload"]
    if not data:
        return FrameView(
            summary=f"ENIP 命令 0x{command:04X}（无数据块）",
            fields=tuple(fields),
            is_exception=header["status"] != 0,
            exception_code=header["status"] or None,
        )

    if not layout.carries_cip:
        # 封装层命令的数据块不是 CIP 消息
        fields.append(FrameField("数据块", _format(data)))
        return FrameView(
            summary=f"ENIP 命令 0x{command:04X}",
            fields=tuple(fields),
            is_exception=header["status"] != 0,
            exception_code=header["status"] or None,
        )

    try:
        send = framing.parse_send_data(data)
    except ValueError as exc:
        return FrameView(summary=f"解析失败：{exc}", fields=tuple(fields))

    cip_data = b""
    for item in send["items"]:
        if item["type_id"] == framing.ITEM_UNCONNECTED_DATA:
            cip_data = item["data"]
    if not cip_data:
        fields.append(FrameField("数据块", _format(data)))
        return FrameView(summary=f"ENIP 命令 0x{command:04X}（无 CIP 消息）", fields=tuple(fields))

    try:
        cip_fields, detail, is_exception, code = _cip_fields(direction, cip_data)
    except ValueError as exc:
        return FrameView(summary=f"解析失败：{exc}", fields=tuple(fields))

    fields.extend(cip_fields)
    return FrameView(
        summary=f"ENIP 命令 0x{command:04X}，CIP {detail}",
        fields=tuple(fields),
        is_exception=is_exception,
        exception_code=code,
    )
```

创建 `icsgen/protocols/enip/adapter.py`：

```python
"""ENIP / CIP 协议适配器。

把一次操作变成协议帧：封装层操作产出 ENIP 封装头 + 该命令自己的数据块；
CIP 操作产出 ENIP 封装头 + SendRRData 数据块 + CIP 消息（服务码 + 路径 +
数据）。一次操作产出请求与响应两帧，响应由服务端发往客户端。

路径（EPATH）不是布局字段 —— 它由 catalog 的 class_id / instance_id /
attribute_id 参数拼装，因此边界变体的上界要由适配器自己顶：
``plan_variant`` 只认布局字段，看不见路径参数。
"""

from __future__ import annotations

from pathlib import Path
from typing import Any

from ...codec.encoder import encode
from ...spec.catalog import Catalog, OperationEntry, load_catalog
from ...spec.model import Operation, Variant
from ..base import BuildContext, FrameView, OperationSpec, ProtocolFrame
from ..variants import plan_variant
from . import cip, epath, framing
from .inspect import inspect_frame
from .layouts import EnipLayout, get_layout

#: catalog 文件位置
CATALOG_PATH = Path(__file__).resolve().parent / "catalog.yaml"

#: CIP 异常响应的通用状态码：路径段错误
CIP_EXCEPTION_CODE = 0x04

#: 封装层错误的封装状态码：非法命令
ENIP_STATUS_INVALID_COMMAND = 0x0001

#: 边界变体要顶上界的参数（路径参数与承载的服务码）
_BOUNDARY_PARAMS = ("cip_service", "class_id", "instance_id", "attribute_id")


class EnipAdapter:
    """ENIP / CIP 协议适配器。"""

    name = "enip"

    def __init__(self, catalog: Catalog) -> None:
        self.catalog = catalog
        self.operations = {
            name: OperationSpec(
                name=name,
                summary=entry.summary,
                layout=entry.layout,
                variants=tuple(entry.variants),
                params_schema=entry.params,
            )
            for name, entry in catalog.operations.items()
        }

    def build(self, op: Operation, ctx: BuildContext) -> ProtocolFrame:
        """把一次操作构建成请求帧。"""
        entry = self.catalog.get(op.op)
        layout = get_layout(entry.layout)
        _, plan = self._plan(op)
        command = self._command(entry)
        metadata: dict[str, Any] = {
            "enip_command": command,
            "transport": ctx.transport,
            "is_exception": plan.is_exception,
        }
        if layout.carries_cip:
            service = self._cip_service(entry, layout, op)
            metadata["cip_service"] = service
            path = self._path(entry, op, layout)
            data = encode(layout.layout.request, plan.request_values)
            payload = framing.build_send_data_payload(cip.build_request(service, path, data))
        else:
            payload = encode(layout.layout.request, plan.request_values)
        frame = (
            framing.build_header(
                command,
                len(payload),
                session=framing.SESSION_HANDLE,
                context=framing.build_context(ctx.transaction_id),
            )
            + payload
        )
        metadata.update(plan.metadata)
        metadata["enip_command"] = command
        metadata["is_exception"] = plan.is_exception
        return ProtocolFrame(payload=frame, metadata=metadata)

    def build_response(self, op: Operation, ctx: BuildContext) -> ProtocolFrame | None:
        """把一次操作构建成响应帧。

        CIP 操作的异常变体回 CIP 错误响应（通用状态非 0）；封装层操作的异常
        变体回一个封装状态非 0 的空数据块。畸形帧没有可解析的响应，返回 None。
        """
        entry = self.catalog.get(op.op)
        layout = get_layout(entry.layout)
        _, plan = self._plan(op)
        if op.variant is Variant.MALFORMED:
            return None

        command = self._command(entry)
        metadata: dict[str, Any] = {
            "enip_command": command,
            "transport": ctx.transport,
            "is_exception": plan.is_exception,
        }
        status = 0
        if layout.carries_cip:
            service = self._cip_service(entry, layout, op)
            metadata["cip_service"] = service
            path = self._path(entry, op, layout)
            if plan.is_exception:
                code = int(plan.metadata.get("exception_code", CIP_EXCEPTION_CODE))
                message = cip.build_error_reply(service, code)
            else:
                data = encode(layout.layout.response, plan.response_values)
                message = cip.build_reply(service, 0, b"", data)
            payload = framing.build_send_data_payload(message)
        else:
            if plan.is_exception:
                payload = b""
                status = ENIP_STATUS_INVALID_COMMAND
            else:
                builder = framing.LIST_REPLY_BUILDERS.get(command)
                payload = (
                    builder()
                    if builder is not None
                    else encode(layout.layout.response, plan.response_values)
                )
            metadata["enip_status"] = status

        frame = (
            framing.build_header(
                command,
                len(payload),
                session=framing.SESSION_HANDLE,
                status=status,
                context=framing.build_context(ctx.transaction_id),
            )
            + payload
        )
        metadata.update(plan.metadata)
        metadata["enip_command"] = command
        metadata["is_exception"] = plan.is_exception
        if not layout.carries_cip:
            metadata.pop("exception_code", None)
            metadata["enip_status"] = status
        return ProtocolFrame(payload=frame, metadata=metadata)

    def inspect(self, op: str, payload: bytes, ctx: BuildContext, direction: str) -> FrameView:
        """解析一帧请求或响应，布局按操作名定位。"""
        entry = self.catalog.get(op)
        layout = get_layout(entry.layout)
        return inspect_frame(layout, payload, ctx, direction)

    def _plan(self, op: Operation) -> tuple[EnipLayout, Any]:
        """解析一次操作：catalog 缺省值 + 场景参数 → 布局与取值方案。"""
        entry: OperationEntry = self.catalog.get(op.op)
        layout = get_layout(entry.layout)
        defaults = {
            name: spec["default"]
            for name, spec in entry.params.items()
            if isinstance(spec, dict) and "default" in spec
        }
        maxima = {
            name: int(spec["maximum"])
            for name, spec in entry.params.items()
            if isinstance(spec, dict) and "maximum" in spec
        }
        func_code = entry.func_code if entry.func_code is not None else 0
        plan = plan_variant(
            layout=layout.layout,
            op_name=op.op,
            func_code=func_code,
            params={**defaults, **op.params},
            variant=op.variant,
            maxima=maxima,
            exception_code=CIP_EXCEPTION_CODE,
        )
        return layout, plan

    @staticmethod
    def _command(entry: OperationEntry) -> int:
        """封装层命令码。1 字节服务码的操作一律走 SendRRData。"""
        if entry.code_width == 1:
            return framing.COMMAND_SEND_RR_DATA
        return int(entry.func_code or 0)

    def _cip_service(self, entry: OperationEntry, layout: EnipLayout, op: Operation) -> int:
        """CIP 消息承载的服务码。"""
        if entry.code_width == 1:
            return int(entry.func_code or 0)
        service = self._param_values(entry, op).get("cip_service", layout.cip_service)
        if service is None:
            raise ValueError(f"操作 {op.op!r} 没有可承载的 CIP 服务码")
        return int(service)

    def _path(self, entry: OperationEntry, op: Operation, layout: EnipLayout) -> bytes:
        """按参数拼装 EPATH：类段 | 实例段 [| 属性段]。"""
        values = self._param_values(entry, op)
        class_id = int(values.get("class_id", layout.default_path[0]))
        instance_id = int(values.get("instance_id", layout.default_path[1]))
        segments = [epath.build_class(class_id), epath.build_instance(instance_id)]
        if "attribute_id" in values:
            segments.append(epath.build_attribute(int(values["attribute_id"])))
        return epath.build_path(segments)

    @staticmethod
    def _param_values(entry: OperationEntry, op: Operation) -> dict[str, Any]:
        """catalog 缺省值 + 场景参数；边界变体把路径参数与承载的服务码顶到上界。"""
        values: dict[str, Any] = {
            name: spec["default"]
            for name, spec in entry.params.items()
            if isinstance(spec, dict) and "default" in spec
        }
        values.update(op.params)
        if op.variant is Variant.BOUNDARY:
            for name in _BOUNDARY_PARAMS:
                schema = entry.params.get(name)
                if isinstance(schema, dict) and "maximum" in schema:
                    values[name] = int(schema["maximum"])
        return values


def load_enip_adapter() -> EnipAdapter:
    """加载内置 catalog 并构造适配器。"""
    return EnipAdapter(load_catalog(CATALOG_PATH))
```

**白名单的四个字段（承接裁定 R5 / R6 / R11 / R15）：**

| 概念 | 位置 | 宽度 | 端序 | 守卫 | 说明 |
|---|---|---|---|---|---|
| `length` | 封装头偏移 2 | 2 | little | 无 | 封装层所有帧都有长度字段 |
| `code` | CIP 体偏移 0 | 1 | little | `6F 00` | CIP 服务码；只在 SendRRData 帧里存在 |
| `address` | CIP 体偏移 6 | 2 | little | `6F 00` | 实例号；路径形态统一（裁定 R11），偏移恒为 6 |
| `crc` | `null` | — | — | — | ENIP 没有校验字段 |

- 锚点两个：`frame: 0`（整帧起点）与 `cip: 36`（CIP 消息在整帧里的偏移）。
- 守卫的偏移**相对整帧**（裁定 R15），因此写成 `guard: {offset: 0, bytes: [0x6F, 0x00]}` —— 帧首是 SendRRData 命令（`0x006F` 小端）才成立。
- `code` 的 `min_value` 是 1：CIP 服务码从 `0x01` 起，`0x00` 不是有效服务码（与 Modbus 的功能码下界同理）。

```yaml
# EtherNet/IP + CIP 的变异字段白名单。
#
# 变异规则本身与协议无关，协议相关的是「哪个字节是哪个字段」。语义见
# icsgen/codec/mutation.py 的模块文档串。
#
# 锚点：frame = 整帧起点；cip = CIP 消息在整帧里的偏移
#   （24 字节封装头 + 12 字节 SendRRData 数据块头 = 36）。
# 守卫的偏移相对**整帧**：帧首是 SendRRData 命令（0x006F，小端）时，
# 帧里才有一段 CIP 消息，code / address 才有意义。
protocol: enip
anchors:
  frame: 0
  cip: 36
fields:
  # 封装头长度字段（第 2-3 字节，小端）—— 封装层所有帧都有
  length: {offset: 2, width: 2, endian: little, min_value: 0}
  # CIP 服务码（CIP 体第 0 字节）；服务码从 0x01 起，下界是 1
  code: {offset: 0, width: 1, endian: little, min_value: 1, anchor: cip, guard: {offset: 0, bytes: [0x6F, 0x00]}}
  # 实例号（CIP 体第 6 字节，小端）—— 路径形态统一，偏移恒为 6
  address: {offset: 6, width: 2, endian: little, min_value: 0, anchor: cip, guard: {offset: 0, bytes: [0x6F, 0x00]}}
  # ENIP 没有校验字段
  crc: null
```
